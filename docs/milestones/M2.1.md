# Milestone M2.1 — leakage-safe splits and FS1

M2.1 implements the frozen Week-0 split boundaries and FS1 static features. The Week-0 amendment takes precedence over the superseded v5 dates.

## Materialized training data

Large outputs are under `~/recom/processed/fs1/v1/`:

| Split | Dates | Features | Labels | Rows |
|---|---|---|---|---:|
| Normal training | Apr 12–29 | `normal_train/features.parquet` | `normal_train/labels.parquet` | 722,481 |
| RQ3 randomized training | Apr 22–29 | `random_train/features.parquet` | `random_train/labels.parquet` | 337,933 |

No validation or test table was materialized. Validation and test checks project only `impression_id`, IDs, date/time, `tab`, and `is_rand`; they do not project outcomes. The machine-readable quality report is `~/recom/processed/fs1/v1/data_quality.json`.

## FS1 contract

Each feature row has a stable unsigned 64-bit `impression_id`, source IDs, `date`, and `time_ms`. Static fields are left-joined from `user_features_pure.csv` and `video_features_basic_pure.csv` and prefixed with `user__` or `video__`. The aggregate `video_features_statistic_pure.csv` is excluded.

M2.4a establishes ascending `impression_id` as the canonical physical order. Static joins explicitly preserve the left impression identity, and both features and labels are sorted before writing. Build manifests and positional checks prevent the original normal-row ordering defect from recurring.

Categorical codes are not ordinally transformed or imputed. Strings remain strings; released numeric category codes retain their numeric storage type. Released nulls remain null. Unknown dimension keys retain the impression, produce null static fields, and set `user__static_missing` or `video__static_missing`. No unknown dimension keys occur in the two current training outputs.

`context__tab` is contextual, not static. `context__is_rand` is physically aligned across sources but the feature selector excludes it from baseline and random-only workflows; only `rq3_joint` can request it. The 44 baseline model fields and 45 RQ3-joint fields otherwise share one schema.

Labels are stored separately and aligned by `impression_id`. `click_semantics` labels tab 1 as `valid_play`, tab 0 as `literal_click`, and other tabs as `unsupported_interface`; it does not modify `is_click`.

## Leakage boundary

Feature construction projects no engagement columns. Outcome loading first authorizes the requested source/date window. Because release rows are not date-contiguous, the bounded reader parses only the first three CSV fields through `date` for every row; only authorized rows are copied into a temporary file whose outcomes are parsed. Non-authorized outcome fields are not returned, stored, tokenized, typed, or materialized.

Reproduce with:

```bash
source .venv/bin/activate
python scripts/build_fs1.py
pytest -q
```

This milestone implements neither FS2/FS3 nor model training.
