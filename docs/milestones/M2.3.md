# Milestone M2.3 — leakage-safe FS3 and neural histories

M2.3 extends FS2 with prior-day user-category affinity and recency features and creates a separate, impression-aligned last-N video-history artifact. It does not train a model or materialize validation or final-test rows.

## Category representation

The official KuaiRand documentation describes `video_features_basic_pure.csv.tag` as a list of key video categories (labels), illustrated by comma-delimited numeric values, but provides no tag-ID codebook. FS3 therefore treats the numeric tokens as opaque identifiers and does not assign names or hierarchy.

The deterministic category key is the complete canonical tag set: trim comma-delimited tokens, remove duplicates, sort numerically, and join with `|`. For example, `65,12,65` becomes `12|65`. Null or empty tags become `__MISSING__`. The released basic-video table has 46 distinct atomic tag IDs, 110 non-missing canonical tag sets, and one missing category, for 111 keys total; 96 of 7,583 videos use the missing category.

Using a complete tag-set key avoids double-counting a multi-tag impression and avoids inventing an unapproved weighting rule across atomic tags. This is a reproducible initial representation, not a claim that each tag set is an ontological category.

## Aggregate feature contract

For target day `d`, affinity and recency aggregates use normal-policy events with `date < d` only. Randomized events, target labels, same-day outcomes, future events, and shipped video aggregates cannot enter these features.

FS3 appends the following fields while preserving every FS2 column and value:

| Feature | Type | Definition |
|---|---|---|
| `category__key` | `String` | Canonical complete tag set or `__MISSING__`. |
| `category__atomic_count` | `Int16` | Number of distinct atomic tag IDs; zero for missing. |
| `user_category__hist_impression_count` | `Int64` | Prior-day normal impressions for the user/category pair. |
| `user_category__hist_long_view_positive_count` | `Int64` | Prior-day long-view positives. |
| `user_category__hist_long_view_rate` | `Float64` | Additive-smoothed long-view rate. |
| `user_category__hist_like_positive_count` | `Int64` | Prior-day like positives. |
| `user_category__hist_like_rate` | `Float64` | Additive-smoothed like rate. |
| `user_category__hist_valid_play_impression_count` | `Int64` | Prior-day tab-1 eligible count. |
| `user_category__hist_valid_play_positive_count` | `Int64` | Prior-day tab-1 valid-play positives. |
| `user_category__hist_valid_play_rate` | `Float64` | Additive-smoothed tab-1 valid-play rate. |
| `user_category__hist_literal_click_impression_count` | `Int64` | Prior-day tab-0 eligible count. |
| `user_category__hist_literal_click_positive_count` | `Int64` | Prior-day tab-0 literal-click positives. |
| `user_category__hist_literal_click_rate` | `Float64` | Additive-smoothed tab-0 click rate. |
| `user__recency_since_last_normal_ms` | `Int64` | Target `time_ms` minus latest prior-day normal user timestamp. |
| `user__recency_missing` | `Boolean` | No valid prior-day user timestamp. |
| `user_category__recency_since_last_normal_ms` | `Int64` | Target timestamp minus latest prior-day matching-category timestamp. |
| `user_category__recency_missing` | `Boolean` | No valid prior-day user/category timestamp. |

Missing recencies are encoded as `-1` and paired with an explicit Boolean indicator. Unseen user/category pairs have zero counts and rates equal to the frozen global prior. Rates use the approved FS2 estimator with `alpha = 20` and the unchanged Apr 9–11 normal burn-in priors. Tab-1 valid play and tab-0 literal click remain separate; other tabs do not enter either click history.

`context__tab` is inherited unchanged. `context__is_rand` is inherited as an RQ3 selector but remains excluded by the existing feature selector outside the joint RQ3 arm.

## Sequence artifact

The initial history length is fixed at `N = 20` without held-out tuning. Each target row has one aligned sequence row containing:

- `history_video_ids`: known raw video ID plus 2; `0` is left padding and `1` is unknown video;
- `history_time_ms`: source timestamps, with padded positions set to 0;
- `history_mask`: `1` for valid history and `0` for padding;
- `history_length`, `target_time_ms`, and `history_tie_boundary_dropped`.

Only normal-policy events with `history.time_ms < target.time_ms` are eligible, including for randomized targets. Histories are ordered by timestamp, encoded video ID, and stable impression ID. Equal-timestamp events are never eligible for a target at that timestamp. If the fixed-length boundary would retain only part of an equal-timestamp group, the entire boundary group is dropped; this prevents arbitrary source-row ordering while retaining a fixed-size tensor.

The sequence deliberately contains no engagement signals. The current protocol does not separately approve their use in neural histories, and adding interface-dependent click values would require a model-input decision beyond M2.3. Video IDs, masks, lengths, and timestamps are sufficient for later pooled-history embeddings without implementing attention or training embeddings now.

## Reproduction

```bash
source .venv/bin/activate
python scripts/build_fs3.py
pytest -q
```

Outputs and the machine-readable report are under `~/recom/processed/fs3/v1/`.

M2.4a rebuilt FS3 and sequence artifacts in canonical ascending `impression_id` order. Feature, label, and sequence IDs must match position by position; the model-input loader fails instead of silently realigning them.
