# Milestone M4.1 — neural training infrastructure

M4.1 implements manifest-bound PyTorch data, shared-bottom MLP, MMoE, ablation, masked-loss, deterministic batching, update accounting, and checkpoint interfaces. It fits preprocessing on authorized April 12–29 normal training only and runs two smoke updates per architecture; no production neural model is trained.

## Inputs and preprocessing

The adapter reads frozen FS3 features plus the separate aligned last-20 history artifact. For normal-only models it excludes `context__is_rand`; a separate `include_is_rand=True` construction path is reserved for a later authorized RQ3 joint-training adapter. It rejects outcome columns, schema drift, noncanonical impression alignment, invalid masks/lengths, nonzero padding, padding ID 0 in valid positions, target-time mismatches, and history timestamps not strictly earlier than their target.

The normal-only dense input has 47 numerical and 36 categorical fields. Every numerical value is imputed with its normal-training median, non-Boolean values are standardized with normal-training mean and standard deviation, and every numerical field receives an explicit missing indicator. Zero-variance scales use 1. Categorical fields use separate sorted training vocabularies with code 0 for missing, 1 for unknown, and 2+ for observed values. User and video IDs use independent vocabularies and embeddings rather than entering the dense categorical collection.

The full encoded width is 286: 94 numerical channels, 36 × 4 = 144 categorical-embedding channels, a 16-dimensional user embedding, a 16-dimensional target-video embedding, and a 16-dimensional history vector. Frozen history video IDs are remapped through the training video vocabulary so target and historical videos share one embedding table. Masked mean pooling ignores padding; an empty history returns the zero vector. No attention or transformer is present.

## Tasks and loss

The three neural heads are long view, like, and tab-1 valid play. Long view and like are eligible on every row. Valid play is eligible only where `click_semantics == "valid_play"`; all other rows receive mask 0 and contribute no valid-play loss. Tab-0 literal click is retained in diagnostics but is not a head in the primary three-task comparison.

Binary cross-entropy is reduced separately as `sum(mask × row_loss) / sum(mask)` for each task, then combined with fixed task weights `[1, 1, 1]`. Thus the larger long-view/like populations do not dominate merely through row count. No positive-class reweighting has been introduced; like's 1.897% prevalence is recorded for later authorized normal-validation tuning.

## Models and ablations

- Shared-bottom: `[128, 64]` ReLU layers, dropout 0.1, then three sigmoid-compatible logits.
- MMoE: four 64-unit experts, one softmax gate per task, 32-unit task towers, dropout 0.1.
- Dense-only MMoE: excludes user ID, target video ID, and history embeddings; input width 238.
- No-history MMoE: retains user/target-video IDs but excludes pooled history; input width 270.
- No-aggregates MMoE: removes dense fields whose names contain `__hist_`, while retaining static/context/recency fields, IDs, and history; input width 220.

The initial infrastructure configuration uses AdamW, learning rate 0.001, constant schedule, weight decay 1e-5, batch size 512, and seeds 0/1/2 with seed 0 primary. These are documented initial settings, not test-tuned results. Training records both examples consumed and optimizer updates so later RQ3 arms can match updates rather than epochs.

## Checkpoints and reproduction

Checkpoint manifests bind model state to architecture, full training configuration, seed, counters, preprocessing checksum, M2 feature-manifest checksum, protocol identifiers, and checkpoint checksum. Loading fails on missing files, stale versions, checksum changes, or incompatible architecture/preprocessing/manifest values.

```bash
source .venv/bin/activate
python scripts/smoke_neural_infrastructure.py
pytest -q
```

Smoke artifacts are under `~/recom/models/neural/infrastructure/v1/`. They are infrastructure checks only and must not be used as production models.
