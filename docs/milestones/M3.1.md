# Milestone M3.1 — R0 historical video-popularity baseline

R0 is a deterministic, non-trained baseline. For each authorized training impression, its score is exactly the frozen FS2 field:

`r0_score = video__hist_long_view_rate`

FS2 constructs that field from normal-policy video outcomes on calendar days strictly before the target day:

`(prior long-view positives + 20 × 0.3364927893253054) / (prior impressions + 20)`

R0 does not recompute this estimator. It verifies the FS2 configuration and M2 feature manifest, then passes the existing value through. An unseen video has zero history and therefore receives the frozen burn-in prior `0.3364927893253054`.

## Input boundary

The scoring component accepts exactly two columns: `impression_id` and `video__hist_long_view_rate`. User IDs/features, user histories, exposure indicators, labels, and all other columns are rejected. The checked feature-only loader validates the `m2-features-v1` FS2 manifest and exact positional ID agreement using only the label artifact's `impression_id` projection; it never projects an outcome column.

Predictions preserve canonical ascending IDs and contain only `impression_id` (`UInt64`) and `r0_score` (`Float64`). Per-split prediction manifests bind them to the corresponding FS2 artifact-manifest checksum.

## Evaluation interface

`evaluate_aligned_r0_predictions` validates an explicit ID-aligned prediction/evaluation pair and delegates to the frozen `within_user_auc` implementation, including the 952-pair sensitivity cap. M3.1 exercises this adapter only with synthetic labels. No training, validation, or test metric was calculated.

## Reproduction

```bash
source .venv/bin/activate
python scripts/score_r0.py
pytest -q
```

Training predictions and the machine-readable quality report are under `~/recom/predictions/r0/v1/`.
