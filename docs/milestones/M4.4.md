# Milestone M4.4 — frozen MMoE ablations

M4.4 trains the three predefined MMoE ablations with seeds 0, 1, and 2. Every production model uses the same April 12–29 normal-training rows, frozen preprocessing and categorical vocabularies, three task masks, equal-weight masked BCE, and 7,060-update budget as the full MMoE.

## Frozen selectors

- `dense_only` (238 inputs): retains the approved dense numerical and categorical FS3 representation; removes separate user ID, target-video ID and pooled-history inputs.
- `no_history` (270 inputs): retains dense FS3 plus user/video ID embeddings; removes pooled history.
- `no_aggregates` (220 inputs): applies the frozen selector that removes dense feature channels containing `__hist_`; retains user/video IDs and pooled history.

The four 64-unit experts, three four-way task gates, three 32-unit task towers, dropout 0.1, and three output heads are unchanged.

The M4.1 dense-only forward selector correctly omitted ID/history inputs but still instantiated unused ID embedding tables. M4.4 repairs that implementation detail for dense-only only: the unused tables are no longer constructed or serialized. This does not change its input or output function, and it leaves full MMoE, no-history, and no-aggregates unchanged. The resulting dense-only model has 133,527 active parameters rather than carrying unrelated frozen parameters.

## Training and artifacts

Train one model with:

```bash
source .venv/bin/activate
python scripts/train_mmoe_ablation.py --ablation dense_only --seed 0
```

Allowed ablations are exactly `dense_only`, `no_history`, and `no_aggregates`; allowed production seeds are 0, 1, and 2. The runner rejects selector drift, input-width drift, unauthorized seeds, changed optimizer/task settings, misalignment, nonfinite outputs/losses/gradients, missing active-parameter gradients, and budget mismatches.

Bundles are stored at `~/recom/models/neural/ablations/v1/<ablation>/seed_<seed>/`. Each contains a checkpoint, architecture-specific checksum manifest, complete update log, and run report. Architecture identities are distinct (`mmoe_dense_only`, `mmoe_no_history`, and `mmoe_no_aggregates`) so incompatible bundles fail loading.

Rebuild and verify the complete nine-bundle manifest with:

```bash
python scripts/summarize_mmoe_ablations.py
```

The manifest is `~/recom/models/neural/ablations/v1/manifest.json`. It independently hashes every checkpoint and verifies its selector, architecture, seed, dimension, update count, example count, and reload result.

An initial temporary attempt to run the three seed-0 models concurrently was stopped before artifact writing because CPU thread oversubscription caused severe throughput degradation. All accepted production bundles were then trained from initialization in isolated sequential processes. No partial state was reused.

No validation outcomes, randomized-validation outcomes, or May 3–8 outcomes were accessed. No full MMoE, shared-bottom, or LightGBM model was retrained.
