# Milestone M2.4a — canonical alignment repair and M2 freeze

## Root cause recorded before repair

The M2.4 gate found identical feature/label ID sets but zero positional matches in all 722,481 normal-training rows. The divergence first occurred in the FS1 user-dimension left join: input impressions and labels were both in ascending `impression_id` order, but the Polars join did not specify `maintain_order="left"` and reordered every normal feature row. The subsequent video join preserved that reordered sequence. Random training happened to retain its original order.

The join remained many-to-one and retained the correct explicit `impression_id`, so feature values were not transferred between impressions. FS2 and FS3 preserved FS1's feature ordering, while their copied labels preserved label ordering. This created a positional-loading hazard even though ID-keyed joins remained correct.

## Repair

`impression_id` ascending is now the canonical physical order for every feature, label, and sequence artifact. FS1 joins explicitly preserve left order, and FS1 features and labels are sorted before writing. FS2 and FS3 features and sequences are also explicitly sorted; downstream labels are copies of the canonical upstream label file.

Every split now has `artifact_manifest.json` with build version `m2-features-v1`, stage, split, row count, canonical order, and feature/label/sequence schemas. The model-input loader checks the manifest, unique/non-null/sorted IDs, exact positional equality, schemas, and row counts. It raises an error and never silently realigns inputs.

All authorized training artifacts were rebuilt in dependency order. A snapshot under `~/recom/processed/m2_4a_pre_repair/` was retained for keyed comparison.

## Before/after result

| Source | Rows | Positional matches before | Positional matches after |
|---|---:|---:|---:|
| Normal training | 722,481 | 0 | 722,481 |
| Random training | 337,933 | 337,933 | 337,933 |

After sorting both sides by explicit ID, every FS1, FS2, FS3, label, and sequence artifact is exactly equal to its pre-repair counterpart. The correction therefore changed physical ordering only; feature values, labels, types, sequence contents, and historical cutoff semantics did not change.

## Frozen feature architecture

- FS1: 50 persisted fields, comprising five alignment fields, 41 released static fields, two unknown-entity indicators, and two context fields.
- FS2: 72 fields; exact FS1 prefix plus 22 prior-day normal-only user/video aggregate fields.
- FS3: 89 fields; exact FS2 prefix plus 17 category-affinity and recency fields.
- Neural history: seven separate aligned fields, including fixed arrays of 20 video IDs, timestamps, and masks.
- Baseline/random-only model selectors expose 44, 66, and 83 fields for FS1–FS3. RQ3 joint exposes 45, 67, and 84 by adding only `context__is_rand`.

The complete machine-readable feature manifest and integration report are under `~/recom/processed/m2/v1/`.
